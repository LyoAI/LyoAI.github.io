LoRA: Low-Rank Adaptation of Large Language Models

LoRA：大语言模型的低秩适配
📅 2026-06-14 ⏱️ 8 min read

TL;DR / 概述

LoRA (Low-Rank Adaptation) is a Parameter-Efficient Fine-Tuning (PEFT) method that freezes the pre-trained model weights and injects trainable low-rank decomposition matrices into selected layers. By constraining weight updates to a low-rank subspace ΔW = BA where B ∈ ℝd×r, A ∈ ℝr×k with r ≪ min(d, k), LoRA reduces trainable parameters by up to 10,000× compared to full fine-tuning while maintaining ≥ 95% of full fine-tuning performance. It adds zero inference latency because the low-rank matrices can be merged into the original weights: W' = W + BA.

Background & Motivation / 背景与动机

Full fine-tuning updates all parameters of a pre-trained model for each downstream task. For a 7B-parameter model like LLaMA, this means storing and serving a separate 7B-parameter copy for every task — quickly becoming infeasible in production. Before LoRA, two main approaches existed:

  • Adapter layers: Insert small trainable modules between transformer layers. Works well but adds inference latency because adapters cannot be merged into weights.
  • Prefix tuning / Prompt tuning: Learn soft prompts prepended to the input. Parameter-efficient but takes up valuable context length and underperforms on smaller models.

The key insight of LoRA (Hu et al., 2021) is that the weight updates during fine-tuning have a low intrinsic rank. This is inspired by the observation that over-parameterized models reside on a low-dimensional manifold — the "intrinsic dimension" of the task is far smaller than the model's parameter count.

Key Concepts / 核心概念

Low-Rank Decomposition

A matrix M ∈ ℝm×n of rank r can be factorized as M = UV where U ∈ ℝm×r and V ∈ ℝr×n. Instead of storing m×n parameters, we store r×(m+n). For a weight matrix W ∈ ℝ4096×4096 with rank r=8, this reduces parameters from ~16.8M to ~65K — a 256× reduction.

LoRA Forward Pass

For a pre-trained weight matrix W₀ ∈ ℝd×k, the LoRA-modified forward pass is:

# LoRA forward pass def lora_forward(x): h = W0 @ x # Frozen pre-trained forward pass h += (alpha / r) * (B @ A @ x) # Low-rank update, scaled by α/r return h

Where A is initialized with a random Gaussian distribution and B is initialized to zero — so at the start of training, ΔW = 0 and the model behaves exactly like the pre-trained base.

Scaling Factor α/r

The scaling factor α/r controls the magnitude of the LoRA update. In practice, α is typically set to 2r (so the ratio is 2), meaning the LoRA update is roughly twice the magnitude of the rank alone. This hyperparameter can be tuned — higher α means stronger adaptation but higher risk of overfitting.

Which Layers to Adapt?

The original paper applies LoRA only to the attention weights (W_q and W_v), freezing W_k and W_o. This is the most parameter-efficient configuration. However, more recent work (including my own Astra paper!) shows that adapting all linear layers (attention + FFN) often yields better performance at a modest parameter increase.

Main Content / 主要内容

Why Low Rank Works

The Aghajanyan et al. (2021) "Intrinsic Dimensionality" paper showed that you can fine-tune a model in a random subspace of much lower dimension than the full parameter space and still achieve ~90% of full fine-tuning performance. For example, a 1.5B-parameter model might only need ~200 parameters in the right subspace to solve a given task.

LoRA operationalizes this insight: instead of finding a random subspace, it learns the optimal low-rank subspace during training. The matrices A and B together define this subspace — A projects the input into a low-dimensional space, and B projects back up. The learned subspace is task-specific and captures the directions of greatest change needed for adaptation.

Practical Implementation (HuggingFace PEFT)

# Minimal LoRA setup with HuggingFace PEFT from peft import LoraConfig, get_peft_model from transformers import AutoModelForCausalLM model = AutoModelForCausalLM.from_pretrained("meta-llama/Llama-2-7b-hf") lora_config = LoraConfig( r=8, # Rank — higher = more capacity, more params lora_alpha=16, # Scaling factor (typically 2× rank) target_modules=["q_proj", "v_proj"], # Which layers to adapt lora_dropout=0.05, # Dropout for regularization task_type="CAUSAL_LM" ) model = get_peft_model(model, lora_config) model.print_trainable_parameters() # trainable params: 4,194,304 || all params: 6,742,609,920 || trainable%: 0.0622

Merging for Inference

After training, LoRA weights can be merged into the base model: W' = W + (α/r)·BA. This means inference is identical in speed and memory to the base model — unlike adapter layers which add sequential computation. You can also keep multiple LoRA adapters and hot-swap them at inference time by adding/subtracting the merged deltas.

LoRA Variants & Extensions

  • QLoRA (Dettmers et al., 2023): Combines LoRA with 4-bit quantization. Fine-tune a 65B model on a single 48GB GPU.
  • DoRA (Liu et al., 2024): Decomposes weights into magnitude and direction, applying LoRA only to the directional component. Consistently outperforms vanilla LoRA.
  • LoRA+ (Hayou et al., 2024): Uses different learning rates for A and B matrices, improving convergence speed.
  • Astra (Liu et al., 2026): Uses activation-space tail eigenvectors instead of random initialization for the low-rank subspace — our work!

Key Takeaways / 要点总结

  1. LoRA constrains weight updates to a low-rank subspace ΔW = BA, reducing trainable parameters by orders of magnitude with negligible performance loss.
  2. The low-rank assumption is justified by the intrinsic dimensionality hypothesis — tasks live on low-dimensional manifolds within the full parameter space.
  3. LoRA adds zero inference latency because the low-rank matrices can be merged into the frozen weights: W' = W + BA.
  4. The scaling factor α/r and rank r are the two most important hyperparameters — start with r=8, α=16 and tune from there.
  5. The choice of which layers to adapt matters — attention weights (W_q, W_v) are the most efficient; adapting all linear layers yields the best performance.
